What this page does, calls and stores
Key level
A Custom Key with faction → members and faction → wars. Torn error 16 means one of those two boxes is not ticked.
Torn calls
/v2/key/info once, for your own Torn ID and faction. /v2/faction/wars for the war that is running right now. /v2/faction/{opponent}/members for the other side's roster and their hospital, jail and travel state. /v2/faction/members for our own names, so a claim can say who holds it. Every request is tagged KSWarRoom.
Claim server
Reads and writes the shared DIBS board at ks-war-room-claims.hans-viklund.workers.dev. It is sent only the war ID, a target's Torn ID, your Torn ID and the War Room password.
Your API key
Stays in this browser. It goes to api.torn.com only, in a request header, never in a web address. It is never sent to the claim server.
Stored in this browser
Your Torn key and the War Room password, in this device's local storage. Nothing else. Each has its own Forget button above.
Writes
Nothing in Torn, ever. No attacks, no clicks, no navigation, no page scraping, no background watching, nothing to do with captcha. The only thing this page writes is a line on the faction's own claim board.
FF and Est
Not here. Fair Fight and estimated stats keep coming from FFScouter in the Dibs userscripts, which this page does not touch.

The claim server promises one thing: of two people calling the same target at the same moment, exactly one is granted. It cannot know whose finger moved first — only which request reached it first. This page therefore says who holds a target, never who was quicker.

The countdown beside a claim is this browser's estimate of the server's own clock. The server sets the time and the server decides when a claim is over.
