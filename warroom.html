What this page does, calls and stores

Torn asks every tool that takes a key to say these five things. Here they are, and everything below them is the long version of the same answer.

Data Storage
Temporary (< 1 day). A war's board is deleted by the server after twelve hours without a change.
Data Sharing
Faction. Who holds which target is shown to this faction only.
Purpose of Use
Competitive advantage.
Key Storage & Sharing
Not stored/shared. Your key is never stored on the server, never written to its log, and never shown to another member.
Key Access Level
Public. A custom key with faction → members, wars and user → basic, profile — the key the KS Torn War Dibs scripts use.
DIBS rules
The same rules as KS Torn War Dibs PC and PDA, decided the same way. A target can be called only while the war is live, in hospital with 2:00 or less left, with a Fair Fight of 2.00–3.40. A target with 20% life or less may be called up to Fair Fight 4.50. A target that is online is free for all and cannot be called; when its activity is unknown or the reading is too old, DIBS applies as usual. One active DIBS per member; the first successful DIBS wins and the holder can release it.
Torn calls
/v2/key/info once, for your own Torn ID and faction. /v2/faction/wars for the war that is running right now. /v2/faction/{opponent}/members for the other side's roster: their hospital, jail and travel state, and whether they are online. /v2/faction/members for our own names, so a claim can say who holds it. /v2/user/{target}/profile for the life of a target that is about to leave hospital, which is what low-life DIBS is decided on: only while the war is live (or the page is in simulation) and this page is on screen, only for targets that are not online and have 2:00 or less left, one at a time, each target at most every ten seconds and at most thirty readings a minute — plus one reading when you press Take DIBS on a target above Fair Fight 3.40. When you press Take DIBS the page asks Torn twice before anything is sent, as the scripts do: /v2/faction/wars (is the war still live) and /v2/user/{target}/basic (is the target still in hospital with 2:00 or less). If Torn says no, fails or does not answer within fifteen seconds, nothing is sent. Every request is tagged KSWarRoom, and the page stops itself at 100 requests a minute. Nothing else. The hospital report described below is sent from the roster reading this page already does — it never asks Torn again for it.
The clock
The 2:00 limit is never counted on this device's clock. It is counted on Torn's time when Torn's answers give it, and otherwise on the KS War Room server's time, which comes with every reading of the claim board. The page makes no request for either — it reads the time off answers it already gets — and always takes the earliest time those answers allow, so a target can open a moment late here but not early by this device's doing. Until one of the two has been read, no target can be called. If this device's clock is set forwards or back, the page notices, calls nothing, and reads the time again with the next answer. Advanced says which clock is in use.
Signing in
Your key is sent once to the claim server, which asks Torn whose key it is and whether that person is in this faction. If so it hands back a signed slip that says your Torn ID and when it runs out. The slip lives in this tab only — not in this browser's storage — and is replaced from your key when it runs out. Your key is not kept by the server for a moment longer than that one question.
Claim server
Reads and writes the shared DIBS board at . That is the KS War Room server — the one KS Torn War Dibs PC and PDA use, so this page and the scripts show and write the same board. Every request is a POST and carries the signed slip in its body: never in a web address, never in a header. It is sent the war ID, a target's Torn ID, and the target's hospital end time as Torn reported it. It is never sent your Torn key after the sign-in, and never your FFScouter key.
Who a claim belongs to
The server takes your Torn ID from the signed slip, not from anything this page puts in the request. This page cannot claim, release or empty in anybody else's name, and neither can anyone else in yours.
Releasing a target automatically
When the roster reading above shows a called target back in hospital with a clearly later end time than when it was called, this page tells the server so and the server frees the claim. The reading is the one already on screen — no extra call to Torn is made for it, and the time sent is the time of that reading, not of the message. Nothing is reported from a reading made 45 seconds or less after the claim was taken: Torn may still be showing the hospital time from before it. The server decides; this page only reports. Your own claim the page releases by itself in two cases, as the scripts do: when the target comes online (it is then free for all), and when the target is back in hospital with more than three minutes left (it has been beaten). It says so in the box at the bottom. It never releases anybody else's claim, and it asks Torn nothing extra for this either.
Your API key
Stays in this browser. It goes to api.torn.com in a request header, and to the claim server once at sign-in, in a request body. Never in a web address. Never to FFScouter.
Stored in this browser
Your Torn key and your FFScouter key if you gave one, in this browser's local storage on this device, as plain text — this page does not encrypt them. They stay until you press Forget key or clear the browser's site data. The column you last sorted the list by is kept there too. Nothing else — and not the sign-in slip. Each key has its own Forget button above.
Writes
Nothing in Torn, ever. No attacks, no clicks, no navigation, no page scraping, no background watching, nothing to do with captcha. The only thing this page writes is a line on the faction's own claim board.
FF and Est
From FFScouter — not from Torn, and not from our claim server. With an FFScouter key on this page, this browser asks ffscouter.com for Fair Fight and estimated battle stats for the targets on the list: one request for the whole list, at most every five minutes, only while the page is on screen. It sends that key and the targets' Torn IDs, nothing else. Without a key the two columns show a dash, nothing is sent, and no target can be called — calling needs a target's FF to be known, so that it can be checked against your FF range. Figures older than fifteen minutes are marked stale; older than thirty they are dropped and the cells say UNKNOWN.

Emptying a war's board is only possible in simulation, and only for the Torn IDs the server has been told may do it. Use Reset test war above the list. Against a real war the server refuses it, for everyone.

The claim server promises one thing: of two people calling the same target at the same moment, exactly one is granted. It cannot know whose finger moved first — only which request reached it first. This page therefore says who holds a target, never who was quicker.

The countdown beside a claim is this browser's estimate of the server's own clock. The server sets the time and the server decides when a claim is over.
